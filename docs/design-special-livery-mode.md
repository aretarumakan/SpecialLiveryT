# 改造設計: 特別塗装機モード（FlyTeam 特別塗装データベース連携）

作成日: 2026-09-13　対象: 空港ウォッチ v2（daisho 所有 GAS）

## 1. 結論（できる／できない）

| やりたいこと | 可否 | 方法 |
|---|---|---|
| 特別塗装機だけを表示する | **できる** | 表示モード切替を追加。判定は既存の `SPECIAL_LIVERIES` を外部マスタ化して使う |
| FlyTeam の登録機体を判定に使う | **できる** | API は無いが、§4b の自動巡回か §4 の貼り付け取り込みでマスタに入れる |
| FlyTeam を GAS が 1 日 1 回自動巡回 | **技術的にはできる（§4b）** | 再検証の結果、GAS の User-Agent では 200 が返る（最初の 403 は汎用 UA によるもの）。HTML は構造が単純で `?pageid=N` でページング。ただし規約に「承諾なく複製・編集・頒布」禁止があるため、私的利用・低頻度・最小項目に限定する |
| 特別塗装機が「今日本のどこにいるか」を一覧で見る | **できる** | adsb.lol の複数 hex 一括照会 `/v2/hex/{hex1},{hex2},...` を確認済み。マスタ全機を 1 リクエストで取れる |
| 自分の空港に特別塗装機が来るとき通知 | **できる（任意）** | 時間主導トリガー + メール。フェーズ3 |

FlyTeam 側の情報構造（確認済み）
- 特別塗装機 DB: https://flyteam.jp/aircrafts/liveries （全 1,399 件）
- 航空会社別一覧: `/airline/{jal|ana|skymark|airdo|...}/livery`（20 件ずつページング。JAL 142 / ANA 89 / スカイマーク 25 / AIR DO 15）
- 機体別ページ: `/registration/{登録記号}/livery/{id}`
- 各行にあるもの: 塗装名（英名/和名）、期間「2026年06月04日 〜」または「〜 2025年12月01日」（終了）、登録記号、説明文
- ユーザーが最初に示した `/aircrafts/registration` は新規登録・抹消登録の一覧で、特別塗装の一覧ではない（隣の「特別塗装」タブが該当）

## 2. 全体構成

```
┌ FlyTeam（ブラウザで閲覧）
│   └ 航空会社別 特別塗装一覧ページ  ──（人が全選択コピー）──▶ ┐
│                                                               │
├ Google スプレッドシート「特別塗装マスタ」                        │
│   ├ シート「マスタ」  登録記号 / 塗装名 / 航空会社 / 期間 / 状態 / hex / 出典URL / 有効
│   └ シート「取り込み」 貼り付け欄  ◀────────────────────────────┘
│         └ GAS 関数 importFromPastedText() が解析 → マスタへ追加・更新
│
├ GAS（空港ウォッチ）
│   ├ getAirportStatus(icao)          既存。special 判定をマスタ由来に置換
│   ├ getSpecialFleetStatus()         新規。マスタ全機の現在位置を 1 回で取得し最寄り空港を付ける
│   ├ getLiveryMaster()               新規。シートを読み CacheService 10 分キャッシュ
│   └ fillHexFromRegistration()       新規（管理者用）。hex 未設定行を adsbdb で補完
│
└ Index.html
    ├ ヘッダにモード切替 「全機体 / ★特別塗装のみ」
    ├ 特別塗装のみモード: 3タブは特別塗装機だけを表示、件数は「特別/全体」
    └ 新タブ「全国」: 特別塗装機が今どこにいるか（駐機空港 / 飛行中→目的地 / 受信なし）
```

## 3. データ設計（スプレッドシート「特別塗装マスタ」）

シート「マスタ」（1 行 = 1 塗装。同じ機体が塗り替えで複数行になってよい）

| 列 | 例 | 備考 |
|---|---|---|
| 登録記号 | JA819A | 必須。大文字・ハイフン込み |
| 塗装名 | ポケモンジェット 赤 | FlyTeam の和名を採用 |
| 航空会社 | 全日空 | |
| 機種 | B787-8 | 空でも可（ADS-B の機種で補う） |
| 開始日 | 2026-07-29 | 「2026年07月」のように日が無い場合は 1 日 |
| 終了日 | （空） | 空 = 運航中。FlyTeam の「〜 2025年12月01日」を反映 |
| 状態 | 運航中 / 終了 / 予定 | 開始・終了日から自動計算しつつ手で上書き可 |
| hex | 86d310 | ICAO 24bit。空なら管理者関数で adsbdb `/v0/aircraft/{reg}` の `mode_s` を補完 |
| 色 | #f4c20d | UI のアクセント。任意 |
| 出典URL | https://flyteam.jp/registration/JA819A/livery/1524 | 任意 |
| 有効 | TRUE | FALSE で一時的に除外 |

判定ルール: `有効 = TRUE` かつ `状態 = 運航中`（または 終了日 が空か未来）の行だけを「特別塗装」とみなす。終了塗装は残しておき、UI には出さない。

初期データ: 現在 `Liveries.gs` にある 11 機をそのままシートに移す。`Liveries.gs` の `SPECIAL_LIVERIES` はシートが読めない時のフォールバックとして残す。

## 4. FlyTeam からの取り込み（半自動）

自動巡回（§4b）を使わない場合、または巡回対象外の塗装を足す場合の手段。ブラウザで見えるテキストを貼るだけで済むようにする。

手順（PC でも iPad でも可）
1. FlyTeam の `/airline/jal/livery` などを開く（20 件ごとに「次の20件」）
2. ページ全体を選択してコピー（iPad は「すべて選択」→コピー）
3. スプレッドシートの「取り込み」シート A1 に貼り付け、メニュー「特別塗装 ▸ 貼り付けを取り込む」を実行

`importFromPastedText()` の解析ルール（ページテキストは確認済みの形式）
- 1 件は「塗装名（1〜2 行）→ 期間行 → 登録記号行 → 説明文」の順で並ぶ
- 期間行: `^(\d{4})年(\d{2})月(?:(\d{2})日)? 〜(?: (\d{4})年(\d{2})月(?:(\d{2})日)?)?$`
- 登録記号行: `^([A-Z0-9]{1,2}-?[A-Z0-9]{3,5})$`（JA819A, EI-HXI, B-58554, N884FD など）
- 期間行の直前 1〜2 行が塗装名。2 行あれば「英名 / 和名」で、和名（2 行目）を塗装名、英名を補足に入れる
- 既に同じ「登録記号 + 塗装名」の行があれば期間・状態のみ更新、無ければ追加
- 取り込み結果（追加 n 件 / 更新 m 件 / 解析できなかった行）を「取り込みログ」シートに残す

補助
- 「hex を補完」メニュー: hex 空欄の行を adsbdb `/v0/aircraft/{reg}` で埋める（fetchAll、1 回 30 件まで）
- 「状態を再計算」メニュー: 今日の日付で 運航中/終了/予定 を更新
- 月 1 回程度、Claude Code に「FlyTeam の JAL/ANA/スカイマーク/AIR DO の特別塗装ページを Chrome で開いて取り込みシートに貼って取り込みを実行して」と頼めば、人手ゼロで回せる（今回の調査と同じ操作）

## 4b. 1 日 1 回の自動巡回（GAS 時間トリガー）— 選択肢として

### 検証結果（2026-09-13）
- `curl -A "<GAS の UA>" https://flyteam.jp/airline/jal/livery` → **HTTP 200**（CloudFront + Apache。Cloudflare の bot 検知ではない）。§1 で「403」と書いた初回テストは UA が `Mozilla/5.0` だけの汎用値だったため弾かれていた
- 一覧 HTML は `<li class="airline-list__item">` 1 件ごとに
  - `a[href="/registration/{登録記号}/livery/{id}"][title="特別塗装機：{塗装名}"]`
  - `.airline-list__sub`（英名・任意）/ `.airline-list__headline`（塗装名）/ `.airline-list__date`（`2026年06月04日 〜` または `… 〜 2025年12月01日`）/ `.airline-list__number`（登録記号）
- ページング: `/airline/{code}/livery?pageid=2,3,4`（20 件/ページ）。JAL 8 ページ・ANA 5・スカイマーク 2・AIR DO 1 → 日本の主要社で **20 ページ弱 / 日**
- 利用規約（/docs/terms）: 「クロール」「スクレイピング」の明示禁止は無し。禁止事項は「不正アクセスで運営を妨害」「承諾なく複製・編集・頒布・転売」「営利目的」

### 規約面の整理（判断は所有者）
- 1 日 20 リクエスト・2 秒間隔は「運営を妨害」には当たらない規模
- グレーなのは「複製・頒布」。Web アプリは匿名公開（ANYONE_ANONYMOUS）なので、FlyTeam の説明文や写真まで転載すると頒布に近づく
- 推奨する線引き
  1. 取り込むのは **登録記号・塗装名・期間・出典 URL の 4 項目だけ**（事実情報。説明文・画像は取らない）
  2. アプリでは塗装名の横に FlyTeam の機体ページへのリンクを出す（出典明示・送客）
  3. 頻度は 1 日 1 回、深夜、失敗時は翌日まで再試行しない
  4. 公開範囲を「自分＋家族」程度に留めるか、心配なら Web アプリのアクセスを「ドメイン内」や「自分のみ」に落とす
  5. FlyTeam から要請があれば止められるよう、トリガーは 1 関数に集約しスイッチ（設定シートの `自動巡回 = ON/OFF`）を置く

### 実装設計 `syncLiveriesFromFlyTeam()`
```
設定シート「巡回」: 航空会社コード一覧（jal, ana, skymark, airdo, jetstar-japan, peach, solaseed-air, starflyer, ibex, ...）, 自動巡回 ON/OFF, 最終実行, 最終結果
1. ON でなければ終了
2. 各航空会社について pageid=1 を fetch（UrlFetchApp、muteHttpExceptions）
   - 200 以外 → その会社はスキップし結果に記録（翌日再試行）
   - 「全 N 件」から総ページ数を求め、pageid=2.. を順に fetch。各 fetch の間に Utilities.sleep(2000)
3. 各ページを正規表現で解析（HTML は安定しているので XmlService は使わず regex）
   /<li class="airline-list__item">([\s\S]*?)<\/li>/g → 各ブロックから
   href="/registration/([^/]+)/livery/(\d+)"、title="特別塗装機：([^"]+)"、
   class="airline-list__date">\s*([^<]+?)\s*<、class="airline-list__number">\s*([^<]+?)\s*<
4. 期間文字列 → 開始日/終了日（§4 と同じ regex）。終了日あり → 状態=終了、開始が未来 → 予定、他 → 運航中
5. マスタと突合（キー: 登録記号 + FlyTeam の livery id）。新規は追加、既存は期間・状態を更新。手入力列（色・有効・メモ）は触らない
6. hex 空欄の新規行は adsbdb で補完（§4 の関数を呼ぶ、30 件/回）
7. 実行ログシートに 追加/更新/失敗ページ を 1 行追記。3 日連続で全滅なら所有者にメール
実行時間の見積: 20 ページ × (fetch 0.5s + sleep 2s) ≈ 1 分。GAS の 6 分制限内
トリガー: 時間主導・日次・午前 3〜4 時（installTrigger() で作成。多重登録防止に既存トリガーを削除してから作る）
```

### 半自動（§4）との使い分け
- 自動巡回 ON なら §4 の貼り付け取り込みは「巡回対象外の航空会社（海外社など）や、FlyTeam に無い塗装を足すため」の補助手段になる
- 自動巡回はいつでも OFF にでき、OFF にしてもマスタは残る

## 5. サーバー側（Code.gs）変更

### 5.1 getLiveryMaster()
- `SpreadsheetApp.openById(LIVERY_SHEET_ID)` → 「マスタ」シートを読む → `{ JA819A: {name, airline, type, color, since, until, hex, url}, ... }`
- CacheService に 10 分キャッシュ（JSON は数十 KB なので 100KB 制限内。超えたら登録記号→塗装名だけに縮約）
- 失敗時は `SPECIAL_LIVERIES` を返す
- `normalizeAircraft_()` の `SPECIAL_LIVERIES[reg]` をこのマスタ参照に置換。既存の `special` オブジェクト形（airline/type/name/note/color）は維持して UI 側の変更を最小にする

### 5.2 getSpecialFleetStatus()（新規・「全国」タブ用）
1. マスタから有効 hex 一覧を取る（hex 無い行は登録記号で `/v2/reg/{reg}` を個別照会。上限 10 件/回）
2. `https://api.adsb.lol/v2/hex/{hex,hex,...}` を 1 回呼ぶ（確認済み: 複数指定可。受信中の機体だけ返る）
   - URL 長対策: 40 件ずつに分割して fetchAll
3. 各機について
   - `alt_baro == 'ground'` → 最寄り空港（AIRPORTS から haversine 最小、3nm 以内）を「駐機中」
   - 飛行中 → 便名で adsbdb 経路（既存キャッシュ流用）→ 「出発地 → 目的地、目的地まで約 n 分」
   - 応答に無い機体 → 「受信なし（格納庫・海外・電波外）」。最後に見た位置を PropertiesService に記録して「最終 xx:xx 羽田」を出す
4. CacheService 25 秒キャッシュ（複数利用者で 1 回に集約、既存と同じ方針）
5. 戻り値: `[{reg, livery, airline, state: 'ground'|'airborne'|'unseen', airport, route, etaMin, lastSeen, photoKey}]` を「自分の選択空港に関係する機体 → 駐機 → 飛行中 → 受信なし」の順に並べる

### 5.3 通知（フェーズ3・任意）
- `checkSpecialArrivals()` を 5 分ごとの時間トリガーで実行
- 設定シート「通知」: 監視空港（複数可）、通知先メール、通知する塗装（空=全部）
- 「駐機中になった」「到着予定 30 分以内に入った」を PropertiesService の前回状態と比較し、変化時だけ `MailApp.sendEmail`（GAS 無料枠 100 通/日で十分）
- LINE Notify は 2025 年に終了しているので使わない。Google Chat Webhook は任意で追加可

## 6. 画面側（Index.html）変更

- ヘッダ右にトグル `全機体 | ★特別塗装のみ`（localStorage に保存、URL は `#RJTT&special=1` でも指定可）
- 特別塗装のみモード
  - 3 タブとも `special` のある機体だけを描画。空なら「この空港に特別塗装機はいません。『全国』で探せます」
  - タブの件数表示を `★2 / 17` の形にする（特別 / 全体）
  - 既存の「周辺を飛行中の特別塗装機」枠はこのモードでは「到着予定」の下に統合
- 新タブ「全国」（両モードで表示。特別塗装のみモードでは初期タブにする）
  - `getSpecialFleetStatus()` を同じ 30 秒サイクルで呼ぶ（選択空港の取得と `Promise.all` 相当で並行）
  - カード: 写真（既存 Planespotters の仕組みをそのまま流用、登録記号キーで共有キャッシュ）＋ 塗装名 ＋ 状態行
    - 駐機中: 「那覇（OKA）に駐機中」→ タップでその空港に切替
    - 飛行中: 「羽田 → 新千歳　あと約 40 分」
    - 受信なし: 「受信なし（最終 08:12 羽田）」を薄色で
  - フィルタチップ: 航空会社（JAL / ANA / SKY / ADO / その他）、「運航中のみ」既定 ON
- マスタの塗装名・出典 URL をカードの特別塗装ノートに表示（出典があれば FlyTeam へのリンク）

## 7. 段階分け

| フェーズ | 内容 | 目安 |
|---|---|---|
| 1 | スプレッドシート化 + 貼り付け取り込み + hex 補完 + 特別塗装のみモード | 半日 |
| 2 | 「全国」タブ（複数 hex 一括照会） | 半日 |

## 8. リスク・制約

- **FlyTeam の規約**: 個人利用でページを閲覧・手動コピーする範囲に留める。自動巡回や再配布はしない。取り込んだデータは自分のシート内のみで使う
- **adsb.lol のレート**: 複数 hex 照会は 1 リクエストにまとまるので現行と同程度（空港 1 回 + 全国 1〜3 回 / 30 秒）。CacheService で利用者間共有
- **hex が取れない機体**: 新造機・登録直後は adsbdb に無いことがある。`/v2/reg/{reg}` で受信時に拾って hex を自動保存する
- **同じ登録記号の塗り替え**: 終了日を入れて別行を追加する運用。状態計算で最新の運航中 1 行だけが有効になる
- **受信なし = いない、ではない**: 格納庫内・エンジン停止で ADS-B が止まっている機体は見えない。UI の文言で明示する
- **シート読み取りの権限**: 既存のスコープに `spreadsheets` が増えるので、次回デプロイ時に所有者の再承認が 1 回必要
